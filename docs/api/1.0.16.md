## A. 네트워킹과 접속

### A1. 클라이언트 접속 경로
`FejdStartup.ParseArguments()`는 `private`이다. `FejdStartup.Awake()` **첫 줄**에서 호출되며, `AwakePlatforms()`보다 먼저 돈다.

```csharp
if (text == "-joinserverwithcharacter" && commandLineArgs.Length > i + 3) {
    m_joinServer = new ServerJoinData(new ServerJoinDataDedicated(commandLineArgs[i + 1]));
    SelectCharacter(commandLineArgs[i + 2], FileHelpers.FileSource.Local);
    m_instantStart = true;
    JoinServer();
}
if (text == "-password" && commandLineArgs.Length > i + 1) ServerPassword = commandLineArgs[i + 1];
```

**`-joinserverwithcharacter`의 함정**
- 조건이 `Length > i + 3`이다. 따라서 `<ip:port> <캐릭터파일명>` 뒤에 **인자가 하나 더** 있어야 한다. 예: `-joinserverwithcharacter 127.0.0.1:54880 thorkell -thorkell-body`.
- `SelectCharacter`가 `PlatformPrefs.SetString("profile", fileName)`을 호출한다. 이것은 **공유 plist에 쓰는 동작**이다. 봇에서는 prefs 쓰기 차단 패치가 먼저 걸려 있어야 한다.
- 순서상 `-password`가 뒤에 오면 `JoinServer()`가 먼저 실행된다. 그래도 비밀번호는 나중에 `RPC_ClientHandshake`에서 `FejdStartup.ServerPassword`로 읽히므로 문제없다.
- `JoinServer()`가 Awake 안에서, 플랫폼 초기화(`AwakePlatforms`)보다 먼저 돈다. 안에서는 `PlatformManager.DistributionPlatform.PrivilegeProvider.CheckPrivilege(...)`와 `MultiBackendMatchmaking.GetServerMatchmakingData`를 쓴다. 이 시점에 정상 동작하는지는 **런타임으로 검증해야 한다**.
  - `MultiBackendMatchmaking.s_instance`가 null이면 `ServerMatchmakingData.None`을 돌려주고 에러 로그만 남긴다.
- **권장:** Eira처럼 메뉴가 준비된 뒤에 직접 접속하는 경로를 쓴다(A2). 이 경로는 검증된 적이 있고 타이밍을 우리가 통제할 수 있다. 네이티브 플래그는 선택 사항으로 남긴다.

**`FejdStartup.JoinServer()`** (public). Dedicated(IP) 타입일 때 흐름:
1. `ZNet.SetServer(false, false, false, "", "", null)`
2. `ZNet.ResetServerHost()`
3. `MultiBackendMatchmaking.GetServerIPAsync(...)`. 리터럴 IP면 즉시 성공한다.
4. 백엔드 결정:
   - `PlayFabManager.IsLoggedIn`이면 `ZPlayFabMatchmaking.FindHostByIp(endPoint, onFound, onFailed, joinLobby:true)`를 부른다.
   - `FindHostByIp`는 `!hostIp.IsPublic`이면 **즉시 `failedAction(EndPointNotOnInternet)`**을 부른다. 127.0.0.1은 public이 아니므로 바로 `ZNet.SetServerHost(ip, port, OnlineBackendType.Steamworks)`로 간다. PlayFab 조회 지연은 없다.
   - 로그인이 안 돼 있으면 처음부터 Steamworks로 간다.
5. `ServerListGui.AddToRecentServersList(GetServerToJoin())`: 최근 서버 목록을 저장한다(B4 참고).
6. `TransitionToMainScene()` → `LoadMainSceneIfBackendSelected`. 0.25초 간격으로 최대 50회 재시도한다.

**직접 접속 API** (모두 `ZNet`의 public static)
- `SetServer(bool server, bool openServer, bool publicServer, string serverName, string password, World world)` [E]. 시그니처는 그대로다.
- `SetServerHost(string host, int port, OnlineBackendType backend)` [E]. 이 밖의 오버로드는 `SetServerHost(ulong steamID)`(Steam P2P), `SetServerHost(string playfabRemoteId)`이다.
- `ResetServerHost()`, `HasServerHost()`.
- `FejdStartup.LoadMainScene()`: `private`, 인자 없음 [E]. 리플렉션으로 호출한다.
- `Game.SetProfile(string filename, FileHelpers.FileSource fileSource)`: public static [E].
- `FejdStartup.ServerPassword`: `public static string { get; private set; }`. setter는 `AccessTools.PropertySetter(typeof(FejdStartup), "ServerPassword")`로 접근한다.
  - 클라이언트의 `ZNet.RPC_ClientHandshake(rpc, needPassword, salt)`는 `needPassword`이고 `FejdStartup.ServerPassword != null`이면 자동으로 `OnPasswordEntered`를 호출한다.
  - 따라서 setter에 값을 넣어 두면 명령줄에 비밀번호를 노출할 필요가 없다.
- 클라이언트 연결: `ZNet.Start()` → `ClientConnect()`. Steamworks 백엔드이고 `m_serverSteamID == 0`이면 `Connect(SteamNetworkingIPAddr)` → `new ZSteamSocket(host)` → `SteamNetworkingSockets.ConnectByIPAddress` 순서로 진행한다.

**`ZNet.SendPeerInfo`**: 클라이언트가 보내는 패키지 순서는 다음과 같다.
- `GetUID()`, 버전 문자열, `40u`, `m_referencePosition`, 프로필 이름, `PlayFabManager.instance.PlayFabUniqueId`
  - `PlayFabUniqueId`는 기본값이 `""`라서 PlayFab에 로그인하지 않은 봇도 괜찮다.
- `SimulationDistance`
- 비밀번호 해시(`MD5(password+salt)`), invite secret key
- **Steam 세션 티켓**: `ZSteamMatchmaking.RequestSessionTicket`. 백엔드와 관계없이 항상 보낸다.

### A2. 호스트 쪽 수신 구조

**`ZNet.OpenServer()`** (public)
- 1.0.16에서는 `ZNet.Start`가 아니라 **로케이션 생성이 끝난 뒤** 호출된다. 경로: `ServerLoadWorld` → `ZoneSystem.GenerateLocationsCompleted += OnGenerationFinished` → `if (m_openServer) OpenServer()`.
- 백엔드와 관계없이 항상 `ZSteamMatchmaking.instance.RegisterServer(...)`(Steam 서버 목록 등록)를 부른다.
- 백엔드별 동작:
  - `m_onlineBackend == Steamworks`: `new ZSteamSocket().StartHost()` → `ZNet.m_hostSocket`(private `ISocket`)
  - `m_onlineBackend == PlayFab`: `ZPlayFabMatchmaking.RegisterServer(...)` + `new ZPlayFabSocket().StartHost()` → `ZNet.m_hostSocket`
- `m_onlineBackend`는 `public static OnlineBackendType`이다. enum은 `Steamworks, PlayFab, EOS, CustomSocket, None`이다. 월드 시작 UI에서 crossplay 토글로 정해지고, 전용 서버는 `-crossplay`로 PlayFab이 된다.

**`ZSteamSocket`**
- 정적 필드 `private static ZSteamSocket m_hostSocket`가 **하나** 있다. 인스턴스 필드로 `private HSteamListenSocket m_listenSocket`와 `private Queue<ZSteamSocket> m_pendingConnections`가 있다.
- 생성자:
  - `()`: 호스트용
  - `(SteamNetworkingIPAddr host)`: IP로 접속
  - `(CSteamID peer)`: P2P
  - `(HSteamNetConnection con)`: 받은 연결
- `public bool StartHost()`
  - 정적 `m_hostSocket != null`이면 `false`를 돌려준다.
  - 아니면 `m_listenSocket = SteamNetworkingSockets.CreateListenSocketP2P(0, 0, null); m_hostSocket = this;`를 실행한다.
- **라우팅:** 정적 콜백 `OnStatusChanged`가 모든 Steam 연결을 처리한다.
  - `None→Connecting`으로 바뀐 새 연결은 **어느 listen socket으로 들어왔든** `GetListner()?.OnNewConnection(hConn)`으로 간다. 받는 쪽은 정적 `m_hostSocket`이다.
  - 그다음 `AcceptConnection` → `m_pendingConnections` → `public ISocket Accept()` 순서로 꺼낸다.
- `RegisterGlobalCallbacks()`가 전역으로 `k_ESteamNetworkingConfig_IP_AllowWithoutAuth = 1`을 설정한다. IP 루프백 연결이 인증서 없이 허용되는 이유가 이것이다.
- `GetHostName()`과 `GetEndPointString()`은 `m_peerID.GetSteamID().ToString()`, 즉 숫자 SteamID를 돌려준다.

**`ZNet.CheckForIncommingServerConnections()`** (private, `ZNet.Update`에서 매 프레임)
```csharp
if (m_hostSocket == null) return;
ISocket socket = m_hostSocket.Accept();
if (socket != null) { if (!socket.IsConnected()) { socket.Dispose(); return; }
    ZNetPeer peer = new ZNetPeer(socket, server: false); OnNewConnection(peer); }
```
- `ZNet.m_hostSocket` 하나만 본다. 그래서 PlayFab 호스트에서는 Steam 연결을 받지 않는다.
- `ZNet.Update`는 매 프레임 `ZSteamSocket.UpdateAllSockets`와 `ZPlayFabSocket.UpdateAllSockets`를 **둘 다** 부른다. 우리가 추가로 만든 Steam 소켓도 송수신이 처리된다.
- `private void OnNewConnection(ZNetPeer peer)`: 서버면 `PeerInfo`, `ServerHandshake` 등의 RPC를 등록한다.
- `public ZNetPeer(ISocket socket, bool server)`.

**`ZNet.RPC_PeerInfo(ZRpc rpc, ZPackage pkg)`** (private). 서버 쪽 순서:
1. uid, 버전, network version(40이 아니면 `Error 3`)을 읽는다.
2. refPos, 이름, playfabId, SimulationDistance를 읽는다.
3. `IsAllowed(hostName, name)`: 밴 목록 또는 **비어 있지 않은 permittedlist**에 SteamID가 없으면 `Error 8`.
   - 호스트와 봇이 같은 Steam 계정이므로, 사용자가 화이트리스트를 쓰면 자기 SteamID도 목록에 있어야 한다. 현재 사용자 목록은 비어 있다.
4. 비밀번호 해시(text2)와 invite key(text3)를 읽는다.
5. `if (m_onlineBackend == Steamworks)`:
   - `peer.m_socket as ZSteamSocket`, `ticket = pkg.ReadByteArray()`
   - `ZSteamMatchmaking.VerifySessionTicket(ticket, socket.GetPeerID())`. 내부는 `SteamUser.BeginAuthSession(...) == OK`이다. 실패하면 `Error 8`.
6. `if (m_onlineBackend == PlayFab)`:
   - `new PlatformUserID(peer.m_socket.GetHostName())`. Steam 피어는 숫자 문자열이라 파싱에 실패하고 **LogError**를 남긴 뒤 `None`으로 처리한다.
   - BlockList 검사, `if (!PrivilegeManager.CrossplayAllowed() && platform != peer.platform) Error 10`
   - **`PlayFabManager.CheckIfUserAuthenticated((peer.m_socket as ZPlayFabSocket).m_remotePlayerId, ...)`**: Steam 피어면 `as`의 결과가 null이어서 **NRE가 난다**. 계획에서 짚은 지점이 맞다. 이 예외로 핸드셰이크가 멈춘다.
7. `GetNrOfPlayers() >= 10`이면 `Error 9`.
8. 비밀번호가 다르면 invite key 확인 후 `Error 6`.
9. `IsConnected(uid)`로 중복을 거른다. 기준은 **세션 UID**라서 같은 계정의 두 클라이언트도 통과한다.
10. 피어를 등록하고 `SendPeerInfo`, `SendPlayerList` 등을 보낸다.

### A3. Thorkell.Host 루프백 리스너 설계 (1.0.16 기준)

| 호스트 모드 | 필요한 작업 |
|---|---|
| crossplay 끔 (Steam), Start server 켬 | `OpenServer`가 이미 정적 `ZSteamSocket.m_hostSocket`(P2P)을 만든다. `ZNet.OpenServer` postfix에서 **`SteamNetworkingSockets.CreateListenSocketIP(127.0.0.1:54880, 0, null)`만 추가**하면 된다. 들어온 연결은 정적 host로 라우팅된 뒤 `ZNet.CheckForIncomming`과 Steam 티켓 검증까지 모두 네이티브로 처리된다. 리스너 핸들은 종료 시 `CloseListenSocket`으로 닫는다. |
| **crossplay 켬 (PlayFab)** | ① 루프백 전용 호스트 소켓을 만든다(아래). ② `CheckForIncommingServerConnections` postfix에서 `ours.Accept()` → `OnNewConnection(new ZNetPeer(s, false))`를 부른다(`OnNewConnection`은 private이므로 리플렉션). ③ `RPC_PeerInfo` 백엔드 shim을 건다(아래). |
| Start server 끔 (싱글) | `ZNet.IsSinglePlayer`(= `m_isServer && !m_openServer`)가 true이고, `Menu`가 열리면 게임이 일시정지되는 등 동작이 달라진다. **v1에서는 지원하지 않는다.** |

**루프백 전용 호스트 소켓** (PlayFab 모드)
- `StartHost()`를 쓰면 P2P 리스너(vport 0)까지 열리고 공격 표면이 넓어진다. 그래서 쓰지 않는다.
- 대신 `var s = new ZSteamSocket();`를 만들고, `m_listenSocket`에 `CreateListenSocketIP(127.0.0.1:54880)`을 리플렉션으로 넣는다. 정적 `m_hostSocket`에도 `s`를 넣는다(둘 다 private).
- PlayFab 모드에는 다른 Steam listen socket이 없다. 그래서 정적 host로 라우팅되는 연결은 우리 루프백 연결뿐이다.
- `Close()`가 정적 host를 정리하므로 종료 시 `Dispose()`를 부른다.

**백엔드 shim 두 가지**
- **(권장) transpiler**
  - `RPC_PeerInfo` 안의 `ldsfld ZNet::m_onlineBackend` **2곳**을 `ldarg.1` + `call Shim.BackendFor(ZRpc)`로 바꾼다.
  - `BackendFor`는 우리 루프백 소켓 피어면 Steamworks를, 아니면 원래 값을 돌려준다.
  - 매치 수가 정확히 2가 아니면 패치를 거부하고 리스너를 열지 않는다(fail-closed).
  - 장점: `SendPlayerList` 같은 다른 메서드가 영향을 받지 않는다.
- **(간단) prefix + finalizer**
  - 루프백 피어일 때만 `m_onlineBackend = Steamworks`로 바꿨다가 finalizer에서 복원한다.
  - 부작용: `RPC_PeerInfo`가 끝날 때 부르는 `SendPlayerList()`가 그 한 번만 PlayFab 친구들의 `PlatformUserID`를 Steam 형식으로 잘못 만든다. 서버는 `SendPeriodicData`로 2초마다 다시 보내므로 일시적 오류다.

**같은 계정 Steam 티켓**
- 0.221.12에서 Eira가 실측했을 때 `BeginAuthSession`이 OK였다.
- 1.0.16에서도 `VerifySessionTicket` 구현은 같다. 그러나 **실행 검증(S0/S0b)이 필요하다.**
- PlayFab 호스트에서도 `ZSteamMatchmaking`은 `ZNet.Awake`에서 초기화되므로 검증 호출은 가능하다.

**PlayFab 모드의 플레이어 목록**
- `ZNet.UpdatePlayerList`는 PlayFab 백엔드일 때 Steam 피어의 ID를 `new PlatformUserID(numericSteamId)`로 만든다. 결과는 Unknown 플랫폼이고 값은 null이다. 예외는 나지 않는다(생성자가 로그만 남김).
- 친구 화면의 Thorkell 항목은 플랫폼 ID가 비어 있다. 기능에는 문제가 없다.

### A4. Eira의 루프백 리스너 (NativeSmoke.cs)와 1.0.16에서 바꿀 점

**Eira가 한 일**
- 호스트를 `ZNet.SetServer(true, openServer:false, ...)`로 연다(Steam 백엔드 기본).
- `ZNet.Start` postfix에서 `new ZSteamSocket().StartHost()`를 부르되, `CreateListenSocketP2P`를 prefix로 가로채 `CreateListenSocketIP(127.0.0.1:54879)`을 돌려주게 했다.
- 그렇게 만든 소켓을 `ZNet.m_hostSocket`에 직접 넣었다.

**1.0.16에서 바꿀 점**
- `ZNet.Start` postfix 방식은 여전히 동작한다. 다만 `openServer:true`이면 `OpenServer`가 뒤에 `m_hostSocket`을 덮어쓴다. 테스트 호스트는 `openServer:false`를 유지하거나, A3의 Steam 모드 방식으로 바꾼다.
- `CreateListenSocketP2P` 전역 패치는 같은 프로세스의 다른 P2P 리스너까지 바꾼다. 실제 플레이용 Host에서는 쓰지 않는다. 리플렉션으로 `m_listenSocket`을 넣는 방식이 더 안전하다.

### A5. 접속 직후 시간 제한 (1.0.20에서 확인, 2026-10-17)
- `ZRpc`는 핑이 `m_timeout`(static, 기본 30초) 동안 없으면 소켓을 닫는다. `ZNet.Start`가 `ZRpc.SetLongTimeout(false)`로 30초로 되돌리고, `ZPlayFabSocket`은 접속·백로그 처리 때 `SetLongTimeout(true)`(90초)를 부른다.
- 클라이언트는 접속 뒤 월드 생성기(대체 바이옴 배치 "Placed … altbiome")를 메인 스레드에서 돌리는 동안 핑에 답하지 못한다. 평소 약 20초였고, 같은 맥에서 다른 무거운 게임이 돌 때 44초가 걸려 호스트가 "ZRpc timeout detected"로 끊었다.
- Thorkell.Host는 루프백 리스너를 연 뒤 `ZRpc.SetLongTimeout(true)`를 부른다(public). 게임이 크로스플레이 접속에 쓰는 것과 같은 값이다.

## B. 격리

### B1. 클라우드 세이브
- `FileHelpers.FileSource`는 `[Flags]` enum이다: `Auto=1, Local=2, Cloud=4, Legacy=8`. 확장 메서드는 `IsLocal()`, `IsCloud()`, `IsAutoOrCloud()`이다.
- `FileHelpers` 정적 getter (모두 `assembly_utils.dll`):
  - `CloudStorageSupported => PlatformManager.DistributionPlatform.SaveDataProvider != null`. 식 본문이고 매우 작아서 **인라인될 위험이 있다**.
  - `CloudStorageSupportedAndEnabled => CloudStorageSupported && SaveDataProvider.IsEnabled`
  - `CloudAndLocalStorageSupported => CloudStorageSupported && LocalStorageFallbackSupported`
  - **`CloudStorageEnabled`는 없다.** Eira의 `AccessTools.PropertyGetter(typeof(FileHelpers),"CloudStorageEnabled")`는 null을 돌려주고, `Patch(null)`에서 런타임 예외가 난다.
- Steam 구현은 `Splatform.Steam.SteamCloud`(internal)이다. `IsEnabled => SteamRemoteStorage.IsCloudEnabledForAccount() && IsCloudEnabledForApp()`.
- **권장 패치:** `AccessTools.PropertyGetter(AccessTools.TypeByName("Splatform.Steam.SteamCloud"), "IsEnabled")` prefix에서 `__result=false; return false`.
  - 인터페이스로 가상 호출되므로 인라인 문제가 없다.
  - 패치 후 `FileHelpers.CloudStorageSupportedAndEnabled == false`인지 런타임 self-test로 확인한다.
  - **[실게임 확인 2026-10-02] 플러그인 `Awake`는 `PlatformInitializer.InitializePlatform`(BeforeSceneLoad, 비동기)보다 먼저 돈다.** 이때 `FileHelpers.CloudStorageSupported`나 `Utils.GetSaveDataPath`를 부르면 `PlatformManager.DistributionPlatform`이 null이라 NRE가 난다. 그래서 패치는 `Awake`에서 걸고, 확인은 `PlatformInitializer.InitializeSaveDataStorage`(private static) prefix에서 한다. 이 메서드가 클라우드 저장소를 처음 마운트하는 곳이다. 확인이 실패하면 원본을 건너뛰고 `Quit(2)`한다(`Compat/Isolation.cs`).
  - `PlayerProfile(…, Auto)` 생성자도 이 값을 보고 Local을 고른다.

### B2. 세이브 경로
- `Utils.GetSaveDataPath(FileSource src)`: `CloudStorageSupportedAndEnabled && src.IsAutoOrCloud()`이면 `""`(클라우드)이다. 그렇지 않으면 `m_saveDataOverride ?? Utils.persistantDataPath`(= `Application.persistentDataPath` = `~/Library/Application Support/IronGate/Valheim`)이다.
- `Utils.SetSaveDataPath(string)`와 `ResetSaveDataPath()`는 public static이다 [E].
  - 설치본 `BepInEx.cfg`의 `[Preloader.Entrypoint]`는 `UnityEngine.CoreModule.dll` / `GameObject` / `.cctor`이다.
  - Jotunn 같은 모드가 `FejdStartup.Awake`를 패치해서 동작하므로, 실무상 플러그인 `Awake`는 `FejdStartup.Awake`보다 먼저 돈다. Eira도 `Awake`에서 `SetSaveDataPath`를 호출해 효과를 확인했다.
  - 그래도 `-joinserverwithcharacter`(Awake 안의 `ParseArguments`)와 함께 쓸 때는 self-test로 로그 순서를 확인한다.
- **[확인 2026-10-02] 이 사용자의 실제 캐릭터·월드는 로컬이 아니라 Steam Cloud에 있다.** Steam이 맥에 두는 사본은 `~/Library/Application Support/Steam/userdata/<계정>/892970/remote/{characters,worlds,serverlist}`이다. `IronGate/Valheim/characters`, `worlds`에는 `steam_autocloud.vdf`만 있고, `worlds_local/<월드>/`에는 미니맵 캐시만 있다. 백업·리허설 복사는 이 remote 폴더에서 한다(`thorkell backup`). appid 892970으로 게임을 켜고 끄면 Steam이 자기 장부 `remotecache.vdf`만 고친다.
- 저장 위치:
  - 캐릭터: `SaveSystem.GetCharacterPath(src, name)` = `<SaveDataPath>/characters_local/<name>.fch`(Local) 또는 `/characters/`.
  - 월드: `SaveSystem.GetWorldsSaveRootPath(src)` = `<SaveDataPath>/worlds_local`.
  - 1.0 월드는 chunked 형식이다. `<root>/<world>/`에 `_main.<n>.fwl2`, `_main.<n>.db2`, `.chunks`, `.chunk`가 생긴다. 구형은 `<world>.db`/`.fwl`이다.
  - 백업할 때는 디렉터리 전체를 대상으로 해야 한다.
- 서버만 쓰는 목록: `adminlist.txt`, `bannedlist.txt`, `permittedlist.txt`(`ZNet.Awake`, Local 경로).
- `MuteList.Load()`와 `BlockList.Load()`는 `ZNet.Start`에서 읽는다.

### B3. prefs (같은 bundle id라서 공유됨)
- `PlatformPrefs`(public static class, `assembly_utils`)
  - 쓰기 메서드: `SetFloat`, `SetInt`, `SetString`, `SetBool`(→`SetInt`), `DeleteKey`, `DeleteAll`, `Save`.
  - 읽기 메서드: `GetFloat`, `GetInt`, `GetString`, `GetBool`, `HasKey`.
  - Steam에서는 `IDistributionPlatform.PreferencesProvider`가 기본 인터페이스 멤버로 **null**이다. 그래서 모든 값이 `UnityEngine.PlayerPrefs`로 가고, 실제 파일은 `~/Library/Preferences/com.coffeestain.valheim-steam.plist`이다(bundle id `com.coffeestain.valheim-steam`).
  - 읽기 경로의 `MigratePlatformKeyIfNeeded`가 PlayerPrefs에 쓸 수 있다. 따라서 `PlayerPrefs.Set*/DeleteKey/DeleteAll/Save`도 막아야 한다(Eira 방식).
  - `PlayerPrefs.DeleteKey/DeleteAll/Save`는 InternalCall extern일 수 있다. 패치가 예외 없이 적용됐는지 로그로 확인한다.
- **Harmony로 막을 수 없는 쓰기:** Unity 네이티브가 종료할 때 `Screenmanager Resolution Width/Height`, `Screenmanager Fullscreen mode`, `Screenmanager Window Position X/Y` 같은 키를 plist에 쓴다. 실제 plist에서 이 키들을 확인했다.
  - **[실게임 확인 2026-10-02] 시작할 때도 쓴다:** `unity.player_session_count`, `unity.player_sessionid`, `unity_connect.mega_session_id`, `unity_connect.session_id`.
  - **채택한 대응: `sandbox-exec` 거부 프로파일**(`brain/thorkell/ops/runtime.py`의 `sandbox_profile`). cfprefsd는 클라이언트에게 `user-preference-write`와 plist의 `file-write-data`가 **둘 다** 없을 때만 쓰기를 거절한다. 그래서 둘 다 막는다. 같은 프로파일로 사람의 세이브(`IronGate/Valheim`), 로그 폴더, 실제 설치 폴더 쓰기도 막는다. 작은 C 프로그램으로 확인했다(도메인 하나만 막았을 때는 쓰기가 됐고, 둘 다 막았을 때는 `CFPreferencesAppSynchronize`가 false를 돌려주고 값이 그대로였다).
  - `CFFIXED_USER_HOME`은 prefs를 옮기지 **못한다**(cfprefsd가 무시한다). HTTPStorages와 `Application Support/<bundle id>` 같은 Foundation 앱별 폴더만 옮긴다. 그래도 그 폴더들이 사람 쪽에 섞이지 않게 함께 쓴다. Steam 초기화는 이 환경에서도 문제없었다.
  - 봇이 640x360 창 모드로 정상 종료하면, 사람이 다음에 게임을 켤 때 해상도가 바뀔 수 있다.
  - 대응 1: supervisor가 봇을 띄우기 전에 `defaults export`로 Screenmanager* 키 스냅샷을 떠 두고, 봇이 끝나면 복원한다.
  - 대응 2: 봇은 프로필을 저장(`Game.instance.SavePlayerProfile(true)`)한 뒤 SIGKILL로 종료해서 Unity 종료 루틴을 건너뛴다.
  - 대응 3: 클론의 bundle id를 바꾸고 재서명한다. 앱이 hardened runtime(TeamID RE3E2MC4D9, `com.apple.application-identifier` 엔타이틀먼트 포함)이라 ad-hoc 재서명 시 제한 엔타이틀먼트 문제가 생길 수 있다. **비권장**(위 샌드박스로 대체).
  - 엔타이틀먼트에 `allow-dyld-environment-variables`와 `disable-library-validation`이 있어서 doorstop 주입이 가능하다.
- 게임 언어도 같은 plist의 `PlatformPrefs.GetString("language")`(현재 Korean)를 읽는다. 봇이 사용자와 같은 언어로 뜨는 것은 이 공유 덕분이다.

## D. 플레이어 조작과 상호작용

**이동·입력**
- `public void Player.SetControls(Vector3 movedir, bool attack, bool attackHold, bool secondaryAttack, bool secondaryAttackHold, bool block, bool blockHold, bool jump, bool crouch, bool run, bool autoRun, bool dodge = false)`
  - bool 11개 중 마지막 `dodge`만 선택 인자다. Eira의 10-bool 호출도 컴파일된다.
  - **`movedir`은 `m_lookDir` 기준 상대 좌표다**(z=앞, x=오른쪽). 월드 방향으로 움직이려면 시선을 먼저 맞추거나 상대 좌표로 바꿔야 한다.
  - 붙잡힘·이모트 중 이동하면 해제되고, autoRun은 `m_lookDir` 방향으로 간다.
- `PlayerController.FixedUpdate()`(private)
  - 소유자가 아니면 반환한다.
  - `TakeInput()`이 false면 0입력으로 `SetControls`를 부른다.
  - 그 밖에는 `ZInput.GetButton("Forward"/"Backward"/"Left"/"Right"/"Attack"/"SecondaryAttack"/"Block"/"Jump"/"Crouch"/"Run"/…)`를 `SetControls`로 넘긴다.
  - 봇은 Eira처럼 prefix로 대체한다 [E].
- **`PlayerController.LateUpdate()`**
  - `SetMouseLook(ZInput.GetMouseDelta() * m_mouseSens)`를 매 프레임 부른다.
  - 봇 창에 포커스가 있을 때 마우스를 움직이면 시선이 돌아간다. **LateUpdate도 prefix로 막거나 `GetMouseDelta`를 0으로 만든다.**
- `Player.TakeInput()`(protected override): 채팅·콘솔·인벤토리·메뉴·TextViewer·맵이 열려 있거나, 죽음·컷신·텔레포트 중이면 false다. **창 포커스는 검사하지 않는다.**
- 시선
  - `Character.SetLookDir(Vector3 dir, float transitionTime = 0f)`: `m_lookYaw`(protected Quaternion)를 정한다.
  - `Player.SetMouseLook(Vector2 delta)`: 상대 회전이다. yaw에 delta.x를 더하고 pitch에서 delta.y를 빼며 ±89°로 제한한다.
  - pitch는 `private float m_lookPitch`이다. 조준할 때는 리플렉션으로 값을 넣거나 델타를 계산해서 `SetMouseLook`에 준다.
  - `SetMouseLookForward/Backward(bool includePitch = true)`도 있다.

**hover와 상호작용**
- `Player.FindHoverObject(out GameObject, out Character)`(private)
  - **`GameCamera.instance.transform`에서** 50m `RaycastNonAlloc`(`m_interactMask`)을 쏜다.
  - 첫 히트가 눈(`m_eye`)에서 `m_maxInteractDistance`(public float, 5) + `GetHoverOffset()` 안에 있을 때만 hover로 잡는다.
  - 조준은 카메라 기준이고 거리는 눈 기준이다.
- `Player.UpdateHover()`는 매 `Update`마다 실행된다. 결과는 `public override GameObject GetHoverObject()`와 `public Character GetHoverCreature()`로 얻는다.
- `Player.Interact(GameObject go, bool hold, bool alt)`(private): 공격·회피 중이면 무시하고, `Interactable.Interact(this, hold, alt)`를 부른 뒤 애니메이션을 재생한다.
- 같은 동작을 내는 두 방법:
  - 가상 입력: `ZInput.GetButtonDown("Use")` postfix로 hover 대상에 `Interact(hold:false)`를 일으킨다.
  - 직접 호출: `AccessTools.Method(typeof(Player),"Interact")`를 리플렉션으로 부른다.
- `ZInput`(`assembly_utils`)
  - `public static bool GetButton/GetButtonDown/GetButtonUp(string name)`, `GetMouseDelta()`, `GetMouseScrollWheel()`, `GetKey/GetKeyDown(KeyCode, bool logWarning = true)`.
  - 모두 작은 정적 메서드다. HarmonyX(MonoMod)가 Mono에서 인라인을 막아 주므로 패치할 수 있다(Valheim 모드에서 흔한 패턴).
- `Player.Update`와 `UpdatePlacement`가 쓰는 버튼 이름:
  - 상호작용: `Use`/`JoyUse`(누르면 1회, 누르고 있으면 hold), `AltPlace`/`JoyAltPlace`(alt)
  - 무기 넣기: `Hide`
  - 걷기 토글: `ToggleWalk`
  - 가디언 파워: `GP`
  - 자동줍기 토글: `AutoPickup`
  - 단축바: `Hotbar1..8`, `Hotbar{i}Alt`
  - 건축 모드: 설치 `Attack`, 제거 `Remove`, 회전 `GetMouseScrollWheel()`
- 단축바는 버튼 대신 **public `Player.UseHotbarItem(int index)`**를 직접 불러도 된다.
- 건축 관련 [M4 예고]: `public void SetSelectedPiece(Vector2Int p)`, `private int m_placeRotation`, `public enum PlacementStatus`. 배치와 제거 레이도 `GameCamera` 기준이다.
- 제작대
  - `CraftingStation.Interact(Humanoid user, bool repeat, bool alt)`
  - `Player.SetCraftingStation(CraftingStation)`(public)
  - `UpdateStations`는 **`InventoryGui`가 보이지 않으면 현재 제작대를 해제한다.** 네이티브 제작을 하려면 InventoryGui가 열려 있어야 한다.
  - `CraftingStation.UpdateKnownStationsInRange(player)`가 1초 주기로 주변 제작대를 발견 처리한다.

## F. 버전

- `Version`은 `public abstract class Version`이다. 안에 같은 이름의 중첩 enum `Player`, `World`, `PlayerData`가 있으니 주의한다.
- `public static GameVersion CurrentVersion { get; }` = `(1, 0, 16)`
  - `GameVersion`은 `public struct`이고 필드는 `public int m_major, m_minor, m_patch`이다.
  - `ToString()`은 patch가 0이면 "1.0"이 되고, 음수면 ".rcN"이 붙는다.
  - `TryParseGameVersion(string, out GameVersion)`이 있다.
- `public const uint c_networkVersion = 40u`
  - **const이므로 우리 DLL에 컴파일 시점 값이 박힌다.** 런타임 값은 `typeof(Version).GetField("c_networkVersion").GetRawConstantValue()`로 읽는다.
  - 게임 로그에도 `"Valheim version: 1.0.16 (network version 40)"`이 찍힌다.
- `public static string GetVersionString(bool includeMercurialHash = false)`
  - `GetPlatformPrefix()`가 붙는다. 붙는 경우는 SteamLinux "l", SteamDeck "dw"/"dl", MS "ms", Switch2 "sw2"뿐이다.
  - macOS Steam은 접두사 없이 "1.0.16"이다. Eira의 "0.221.12" 비교는 런타임에 실패해서 플러그인이 꺼진다.
