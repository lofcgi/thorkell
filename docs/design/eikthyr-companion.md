# 설계: 첫 보스(Eikthyr)까지 같이 가는 동료

작성 2026-10-17. 목표(사용자): 토르켈은 자기 캐릭터로 직접 플레이하면서, 사람이 그 자리에서 플레이했다면 얻었을 만큼의 정보를 얻고, 사람처럼 인지·판단·행동한다. 사람과 함께 첫 보스까지 무난하게 깬다.

- "사람과 같은 정보"는 사람 플레이어의 화면을 본다는 뜻이 아니다. 토르켈 자신의 클라이언트에서, 사람이 같은 캐릭터를 조작한다면 화면으로 알 수 있는 양과 종류의 정보를 뜻한다.
- 정보의 양과 종류를 사람과 맞추는 이유는 판단도 사람처럼 하게 하려는 것이다. 게임 내부값은 쓰지 않는다.
- 사람(리더)의 게임에서 오는 것은 사람이 친 채팅뿐이다. 사람도 친구의 채팅은 보기 때문이다.

## 완료 기준

| 항목 | 기준 |
|---|---|
| 같이 플레이 | 사람(리더)과 새 월드에서 시작해 Eikthyr를 함께 처치한다. 토르켈 탓으로 사람이 죽거나 막히지 않는다 |
| 정보 동등성 | 두뇌가 받는 것은 토르켈 자신의 화면에 나오는 것뿐이다(사람이 그 캐릭터를 조작한다면 볼 것). 생물 이름은 게임이 그 생물 위에 이름표를 띄울 때만, 레시피는 제작 메뉴에 열렸을 때만 안다 |
| 자기 판단 | 부탁의 뜻·규모가 모호하면 되묻고, 모르는 이름은 묻거나 찾아본다. 시키지 않아도 배고프면 먹고, 다치면 물러나고, 밤에는 피한다 |
| 장기 목표 | 끼어든 일(습격, 허기, 밤)이 끝나면 하던 일과 큰 목표(예: Eikthyr)로 돌아간다. 목표는 세션을 넘어 남는다 |
| 검증 | 각 능력은 실게임 시나리오로 월드 변화(인벤토리, 대상 HP, 생긴 건물)를 확인한다 |

## 사람의 첫 플레이 흐름 (Eikthyr까지)

근거: `docs/research/2026-10-17-valheim-human-play-observations.md`(영상 분석), `docs/api/early-game.md`(게임 코드).

1. 시작 신전에서 까마귀(Hugin) 안내를 읽는다. 바닥의 나뭇가지·돌을 줍는다.
2. 재료를 주우면 제작 메뉴에 레시피가 열린다. 곤봉·돌도끼·횃불·망치를 만든다.
3. 망치로 작업대를 놓는다. 작업대는 지붕이 있어야 쓸 수 있다. 벽과 지붕으로 작은 집을 짓는다. 모닥불, 침대를 둔다.
4. 멧돼지·사슴을 사냥해 가죽과 고기를 얻는다. 고기는 불 위 요리대에서 굽는다. 산딸기·버섯도 먹는다.
5. 활(가죽 조각 + 나무), 화살, 가죽 방어구를 만든다. 부싯돌로 부싯돌 도구로 바꾼다.
6. 룬스톤·베그비시르가 제단 위치를 알려 준다. 제단 글을 읽고 사슴 트로피 2개가 필요하다는 것을 안다.
7. 음식 3칸을 채우고 제단에 트로피를 바친다. 활로 거리를 두고, 번개 공격을 피하며 싸운다.

## 구조

```
Body (C#, 매 프레임)          Brain (Python)
 지각: 사람이 보는 만큼   ──►   세계 기억(장소·자원·생물) + 지식(이름·레시피·사실)
 행동: 검증되는 원자 동작  ◄──   스킬(코드): 채집·제작·건축·사냥·요리·잠·전투·탐색
 반사: 막기·회피·위험 탈출         필요(배고픔·체력·밤·휴식) → 생존 목표
                                 의제(장기 목표, 저장됨) → 쉬는 시간의 할 일
                                 판단(LLM): 말 이해·되묻기·계획·대답 — 검증기 통과한 계획만 실행
```

- 사람이 정한 명령, 생존, 반사는 모델 없이 바로 돈다. 모델(gemini-3.8-flash)은 새 부탁, 계획, 대화에만 쓴다.
- 모델 출력의 이름은 알고 있는 이름 목록(enum)에서만 고른다. 수치는 코드가 계산한다.

## 몸: 새 동작

| op | 하는 일 | 결과 확인 |
|---|---|---|
| `craft` | 제작대(또는 맨손)에서 레시피를 만든다 | 인벤토리에 만든 물건이 늘어남 |
| `place` | 망치로 건축물 하나를 지정한 자리에 짓는다 | 그 자리에 토르켈이 지은 건물이 생김 |
| `use_item` | 손에 든 물건을 대상에 쓴다(제단에 트로피, 요리대에 날고기, 불에 장작) | 인벤토리 감소 + 대상 상태 변화 |
| `shoot` | 활을 당겨 대상에게 쏜다(이동 예측) | 화살 감소, 대상 HP 감소 |
| `dodge` / `block` | 구르기, 막기 | 상태(회피 중, 막은 피해) |
| `drop` | 물건을 몸 앞에 내려놓는다(건네기) | 인벤토리 감소, 바닥 아이템 |
| `interact` 확인 | 줍기 대상은 인벤토리 증가, 침대는 잠, 문은 열림, 룬스톤은 글 | 대상별 |
| `take_all` | 묘비·상자에서 꺼낸다 | 인벤토리 증가 |
| `repair` | 작업대에서 수리 | 내구도 증가 |

## 지각: 토르켈 자신의 화면에 나오는 만큼

| 정보 | 지금 | 바꿀 것 |
|---|---|---|
| 생물 이름 | 40m 안이면 항상 진짜 이름 | 게임이 이름표(EnemyHud)를 보여줄 거리 안이거나 커서를 올렸을 때만 이름. 그 밖은 "모르는 생물"과 겉모습(크기) |
| 까마귀 안내 | 제목만 | 본문까지 |
| 제작 메뉴 | 없음 | 알려진 레시피·건축물과 재료, 지금 만들 수 있는지, 필요한 제작대 |
| 상태 효과 | 없음 | 휴식, 젖음, 추위 등 화면 아이콘 |
| 지도 | 리더 위치만 | 지도에 생긴 표시(베그비시르가 알려 준 제단 등) |

## 두뇌

- **세계 기억**: 집·작업대·침대·제단 같은 장소, 나무·돌·부싯돌·덤불 위치, 본 생물과 위험했던 곳. 저장된다.
- **필요**: 음식 칸, 체력, 밤, 휴식, 도구 내구도, 가방 무게. 임계값은 히스테리시스를 둔다.
- **의제**: 사람이 말했거나(“Eikthyr 잡자”) 스스로 알게 된(제단 글) 장기 목표. 쉬는 시간에 다음 단계를 고른다.
- **판단(LLM)**: 리더의 말과 지금 상황을 받아 대답, 되묻기, 목표·계획을 낸다. 모르는 이름이 나오면 묻거나 `search`로 찾아본다.

판단과 배움 (2026-10-17 사용자 지적 후)
- 전술을 실패할 때마다 코드 숫자로 고치던 것을 그만뒀다. 그건 개발자가 배운 것이다.
- 코드는 언제 생각할지만 정한다(큰 것이 알아챔·싸움 끝·죽음). 무엇인지·어떻게 싸울지는 모델이 지각(키, 화면 위 체력바, 음식 칸, 무기)과 기억으로 정한다(`plan/tactics.py`).
- 배움은 싸움 기록 → 회고 → 숫자 근거가 든 교훈 → 다음 싸움에서 따르고 판정(가설 → 지지 → 검증/반박)으로 쌓인다(`mind/store.py`).
- 눈은 그대로다. 게임 상태를 사람이 자기 화면에서 알 수 있는 만큼만 읽는 것이 컴퓨터의 눈이다. 픽셀 비전은 쓰지 않는다.

남은 위험
- 잠은 실게임에서 아직 안 해 봤다. 리더 침대 옆에 짓는 자리가 지붕·벽 판정(cover 0.8)을 못 넘으면 "침대를 내 것으로 못 했어"라고 게임 말을 전한다.
- 실제 플래너는 무료 등급이면 하루 호출 수가 적다(`docs/research/2026-10-02-api-costs-and-keys.md`). 정해진 말(따라와, 기다려, 멈춰, 자자, 나무 N개)은 모델 없이 돈다.
